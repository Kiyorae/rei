# macOS UI 改造

## 目标与边界

AppKit 统一管理应用入口、窗口、三栏工作区、消息、输入、设置和检查器。
应用自身的 SwiftUI 视图与 hosting 桥接全部进入移除范围；`AppEnvironment` 继续提供业务状态。
协议事件和保存的消息正文保持原文，Markdown 只作用于显示层。

## 实施顺序

1. 用 `NSApplicationDelegate`、`NSWindowController` 和 `NSSplitViewController` 管理应用与工作区。
2. 用 `NSTableView` 管理聊天列表，区分初始历史与追加消息，维护阅读锚点和引用定位。
3. 接入 AppKit MarkdownView，支持标题、强调、链接、列表、引用、代码块、表格和公式。
4. 加入消息入场、发送反馈、悬浮操作、附件与提及、回应计数及检查器切换动效。
5. 迁移侧栏、全部检查器工具、设置、日志、附件预览和编辑表单，保留原有功能。
6. 移除旧 SwiftUI 页面与桥接，改造原有 UI 测试，验证布局、滚动、草稿隔离、发送失败和减少动态效果。

## 状态与生命周期

- 列表数据源持有当前显示快照，业务更新仍由 `AppEnvironment` 驱动。
- 列表内部负责滚动位置与跟随意图；用户浏览历史时，新消息不改变阅读位置。
- 使用 diffable data source 的稳定消息 ID 提供行内容，保证快照替换时不使用旧行号索引新数组。
- 侧栏与消息列表一次只应用一个快照，合并过渡期间的更新；下一次提交离开 AppKit 当前回调栈后再执行。
- 通用列表用原生非动画 diffable snapshot 一次更新行结构与内容，避免分组移动和摘要刷新分成两个事务而留下旧单元格；快照提交期间保留稳定选择并抑制业务选择回调。
- 复用行不保存业务状态，历史行和复用行不重播入场动画。
- 草稿按会话和发送身份隔离，只有发送成功才清空。
- Markdown 渲染使用当前正文与主题；原文复制和协议序列化不受影响。
- 所有位移、缩放和弹性动效遵循系统减少动态效果设置。

About 的 Logo 保留原始五次点击彩蛋：1.8 秒匀速转两圈，再用 0.7 秒弹性收尾到第三圈。
旋转仅作用于独立的图片图层，按钮位置不变；动画期间忽略点击，离开页面或关闭窗口后清零，减少动态效果开启时停止动画。

## 界面职责

布局参考 Codex 的侧栏、会话画布、底部输入和可折叠详情层次，保持 Rei 的原有业务功能。
侧栏顶部是品牌、新建入口和原生搜索；会话使用系统 source list，统一为头像、名称和单行摘要。
会话列表只保留系统行内缩，选中底色延伸到侧栏两侧；会话和设置侧栏始终采用原生非强调选中态，避免焦点转入内容区时蓝灰切换。
侧栏底部集中展示当前用户的头像、身份、账号和群内角色，以及紧凑的连接状态。
账户菜单提供身份切换和设置入口；设置也可通过应用菜单和 `⌘,` 打开。
工具栏右上角分别提供会话详情和 Events 开关，聊天标题栏不重复提供这些操作。

主窗口使用全尺寸内容区，左右侧栏材质延伸到窗口顶边；内容按系统安全区布局，避开窗口按钮和工具栏。
主侧栏由 `NSSplitViewItem` 提供唯一的系统玻璃，不叠加读取桌面背景的旧材质，也不镜像会话内容到导航区域；光色响应交给原生玻璃处理。
工具栏通过系统 tracking separator 跟随侧栏和详情边界；详情的 separator 显式绑定嵌套的内容 split view。
详情默认收起，保留用户后续的展开状态。Events 通过独立的原生水平分隔面板从会话区和详情区下方展开，左侧栏保持全高。面板可拖动调整高度、通过自身关闭按钮收起，重新打开保留搜索、筛选和事件选择。
主侧栏、详情、Events 高度、设置侧栏和诊断数据分栏都通过原生分隔线拖动调整，并由 AppKit 保存尺寸。面板尺寸保持优先级位于弹性内容与原生拖动之间，避免固定尺寸优先级拦截用户拖动；设置和诊断工具行使用自然高度，确保分栏布局明确。
底部 Events 使用左侧事件列表和右侧原始数据的原生分栏；标题、搜索、Filter、清除、Show All 和关闭操作集中在一行。原生 Filter 菜单选择 All／Received／Sent；菜单勾选和按钮标题显示当前条件，Show All 同时重置方向、搜索和清空标记。
公共操作按钮与下拉菜单使用原生 `NSBezelStyle.glass` 和系统胶囊轮廓，与系统搜索框统一材质；事件筛选、重置与搜索采用同一控件尺寸和字号，按钮保持内容宽度，不叠加自绘玻璃背景。输入区内的附件标签采用原生 accessory 样式，复用外层玻璃材质。
Demo 使用 `NSMenuToolbarItem` 和原生菜单代理，在打开时更新播放和跟随状态，由 AppKit 锚定触发按钮并处理工具栏溢出菜单。

输入区居中并限制最大宽度为 820 点，单层 `NSGlassEffectView` 承载原生 `NSTextView`、附件、提及和发送控件。
阅读区的填充偏好低于面板尺寸保持优先级；达到最大阅读宽度后保留两侧留白，不通过改变侧栏宽度来满足填充约束。
消息阅读区域与输入区对齐，消息列表延伸至窗口底部，输入区以单独悬浮层覆盖其上，不再占据独立的底部背景区域。列表末尾留白随输入区实际高度变化，使最新消息完整显示在输入区上方；浏览历史时消息可从玻璃后方滚过，阅读位置保持稳定。窄高度下编辑区内部滚动，保留会话标题与发送操作。跳转最新消息保留 AppKit 玻璃材质并置于输入区上方。
输入框只接收真实位于玻璃后方的滚动内容及系统原生光色响应，末尾留白保持为空，不镜像或复制上方消息来制造倒影。
引用消息使用独立的作者与正文标签、中性背景和细竖线；正文保持系统主要文字颜色，不因无法跳转而变成禁用态。可跳转时保留整卡点击和原生辅助功能按钮，引用内容更新会重新计算消息行高度。
设置使用独立的原生分栏窗口，左侧 source list 导航，右侧系统 `NSBox` 表单分组；切页保留未保存的配置。
设置行左侧放标题与说明，右侧放按内容定宽的按钮和下拉菜单；长选项受可用宽度约束，编辑字段保留合适的输入宽度，布尔选项采用原生 `NSSwitch`。
About 和会话详情中的操作按钮不再直接承担整行宽度，按钮外的布局容器负责留白与对齐。
玻璃视图自行管理其 `contentView`，内边距放在普通内容容器里，避免与系统约束冲突。
附件由外层消息气泡统一提供背景，空状态行不占空间。
消息单元格发布内容的固有高度，因此转发消息折叠、展开和嵌套内容变化都能正确更新行高。
代码与表格使用可用阅读宽度，普通短消息保持紧凑。

## 参考

参考 [lody-ios](https://github.com/Innei/lody-ios) 的原生列表、滚动锚点与 Markdown 渲染分工。
通过 SwiftPM 使用其 [MarkdownView](https://github.com/Innei/MarkdownView) 分支的固定提交；
使用包的 AppKit 实现，避免引入 UIKit 或 Catalyst。

## 验收

- 主窗口可调整侧栏、详情和底部 Events 面板，折叠与恢复保留事件搜索、筛选与选择。
- 侧栏贯穿顶栏和窗口底边；窄窗口下按钮仍处于各自分区，底部工具行保持紧凑，折叠恢复不改变窗口和侧栏宽度。
- 首次显示历史定位末尾；新消息跟随、历史浏览、引用定位和清空历史正确。
- 长 Markdown、代码、表格、中英文混排在窄窗口和深浅主题下可读并可选择。
- 发送成功有反馈，失败保留草稿；切换会话和身份不串草稿。
- `make quality`、`make test`、Debug 应用构建通过，并运行演示检查可见行为。

## 当前进度

演示窗口已验证原生玻璃输入区、详情折叠、账户菜单和两处设置入口。
